# RosterMind 智排班

RosterMind 是一个面向 **四人、白夜班、全年连续值守** 场景的智能排班网站。项目优先保证四人排班规则正确，再通过员工账户、请假、换班和休息偏好降低管理员的日常协调成本。

UI 采用温和友好的效率工具风格：暖灰背景、柔和紫色与薄荷绿、圆角卡片和清晰的移动端排班卡片。桌面端适合管理排班，手机端适合员工随时查看、请假和换班。

## 当前排班模型

### 班次时间

| 班次 | 时间 | 每日最低在岗人数 | 每日最高在岗人数 |
| --- | --- | ---: | ---: |
| 白班 | 09:00–23:00 | 1 | 2 |
| 夜班 | 23:00–次日 09:00 | 1 | 2 |

### 四人班组规则

- 每周白班组 2 人、夜班组 2 人。
- 每名员工正常每周工作 5 天、休息 2 天。
- 同组两人的休息日不能重叠。
- 除明确选择“优先工作日休”外，每名员工的休息日中至少有 1 天是周六或周日。
- 正常两人班组会分别休周六和周日，因此周末每天每个班次都由 1 人值班。
- 以一个两人班组为例：
  - 员工 A 独立值班 2 天；
  - 员工 B 独立值班 2 天；
  - A、B 共同值班 3 天；
  - 因此完整覆盖一周 7 天，并且两人各工作 5 天。
- 每天白班和夜班都必须至少有 1 人在岗。
- 夜班结束后不能立即衔接当天 09:00 开始的白班。

### 当前特殊阶段

当前允许设置一名员工为“只上白班”：

1. 该员工始终留在白班组。
2. 其余三名可倒班员工按设定周期轮流成为白班搭档。
3. 每个周期剩余两名员工组成夜班组。
4. 倒班周期可设置为 2、3、4 或 5 周。

### 未来四人平等阶段

当所有员工都改为“白夜班均可”后：

- 系统按照轮换顺序组成两个两人小组。
- 两组按照倒班周期互换白班和夜班。
- 在夜班转白班的周期边界，系统会提前预留休息，避免周日夜班直接衔接周一白班。

## 排班约束优先级

### 硬约束

硬约束永远不会为了个人偏好而被破坏：

- 每天白班至少 1 人；
- 每天夜班至少 1 人；
- 正常情况下每人每周工作不超过 5 天；
- 每人正常每周至少休息 2 天；
- 除明确选择“优先工作日休”外，每周至少休息 1 个周末日；
- 只上白班、只上夜班限制；
- 已批准的请假；
- 夜班转白班的安全衔接；
- 同一员工同一天不能同时上两个班次。

如果硬约束互相冲突，系统会拒绝生成排班并说明原因，不会生成一个表面完整但实际不可执行的排班。

### 软偏好

系统在满足全部硬约束后，尽量匹配员工选择的休息方式：

- 优先连休；
- 优先周末休；
- 优先工作日休；
- 优先散休；
- 无特别偏好：默认仍保证至少休息 1 个周末日。

“优先连休”和“优先散休”同样会保留至少 1 个周末休息日；“优先周末休”会在不破坏覆盖的前提下争取更多周末休息。只有明确选择“优先工作日休”时，系统才允许两个休息日都落在工作日。

## 主要功能

### 管理员

- 使用管理员账户登录；
- 创建和停用员工账户；
- 重置员工密码；
- 设置员工为白夜班均可、只上白班或只上夜班；
- 设置员工默认休息偏好和轮换顺序；
- 设置 2～5 周倒班周期；
- 按周智能生成排班草稿；
- 查看规则冲突和夜转白衔接提示；
- 确认后发布排班；
- 审批员工请假；
- 查看全部换班记录和操作审计。

### 公开首页

- 无需登录即可查看当前时间段的在岗人员；
- 无需登录即可查看当前周已经发布的白班、夜班排班表；
- 自动显示当前时间、当前班次和下一班人员；
- 公开页面只展示已发布排班，不展示草稿、请假、换班和个人通知；
- 同时适配桌面端值班看板和移动端快速查看。

### 普通员工

- 查看本周已经发布的排班；
- 查看当前时间点的在岗人员和下一班人员；
- 在排班表中突出显示自己的值班；
- 修改个人休息偏好；
- 提交请假申请；
- 撤销尚未审批的请假；
- 选择自己的值班和对方值班发起换班；
- 同意或拒绝别人发来的换班申请；
- 查看站内通知和历史记录。

### 换班安全规则

第一版只允许 **同一周、同一班次** 的两个值班日期互换：

- 双方交换后每周工作天数保持不变；
- 对方必须登录并同意；
- 目标日期不能已经有重复值班；
- 不能与已批准请假冲突；
- 原排班发生变化时，旧申请自动无法生效。

## Docker 快速部署

### 1. 设置生产密码

复制环境变量示例：

```bash
cp .env.example .env
```

至少修改以下值：

```env
ADMIN_INITIAL_PASSWORD=一个足够强的管理员密码
DEMO_USER_PASSWORD=演示员工密码
POSTGRES_PASSWORD=数据库密码
DATABASE_URL_DOCKER=与数据库密码匹配的容器连接地址
```

正式环境建议设置：

```env
SEED_DEMO_DATA=false
SESSION_COOKIE_SECURE=true
```

`SESSION_COOKIE_SECURE=true` 要求网站通过 HTTPS 访问。

### 2. 启动

```bash
docker compose up -d --build
```

打开：

```text
http://localhost:3000
```

容器启动时会自动：

1. 等待 PostgreSQL 健康；
2. 执行尚未应用的 SQL 迁移；
3. 创建初始管理员；
4. 根据 `SEED_DEMO_DATA` 决定是否创建四名演示员工；
5. 启动 Next.js 生产服务。

### 3. 默认开发账户

仅当没有修改 Docker Compose 默认值时：

| 角色 | 用户名 | 密码 |
| --- | --- | --- |
| 管理员 | `admin` | `RosterMind@2026` |
| 演示员工 | `anxin` / `baichuan` / `chenchen` / `duning` | `Welcome123!` |

请勿在公网环境继续使用默认密码。

### 4. 查看运行状态

```bash
docker compose ps
docker compose logs -f app
```

### 5. 停止或更新

```bash
docker compose down
git pull
docker compose up -d --build
```

默认情况下 `docker compose down` 不会删除 PostgreSQL 数据卷。不要随意使用 `docker compose down -v`，该命令会删除数据库数据。

## 本地开发

需要 Node.js 22.13 或更高版本，以及可用的 PostgreSQL。

```bash
npm install
cp .env.example .env
docker compose up -d db
npm run db:migrate
npm run db:seed
npm run dev
```

如果本机应用通过宿主机访问 Docker 中的数据库，`.env` 使用：

```env
DATABASE_URL=postgresql://roster_mind:roster_mind@localhost:5432/roster_mind
```

## 数据库迁移

SQL 文件位于 `migrations/`。`scripts/migrate.mjs` 会记录已经执行的文件，不会重复应用同一个迁移。

手动执行：

```bash
npm run db:migrate
```

## 生产部署建议

- 使用 Nginx、Caddy 或云负载均衡器提供 HTTPS；
- 设置 `SESSION_COOKIE_SECURE=true`；
- 修改数据库密码和初始管理员密码；
- 设置 `SEED_DEMO_DATA=false`；
- 定期备份 `roster_mind_data` 数据卷或 PostgreSQL 数据库；
- 限制数据库端口，不要直接暴露到公网；
- 反向代理只需要公开应用的 3000 端口；
- 上线前根据实际工作地点核对当地劳动法规。RosterMind 负责执行配置的排班规则，不构成劳动法规合规证明。

## 当前版本边界

- 自动排班器当前要求恰好有 4 名启用员工；添加更多账户不会丢失数据，但需要停用到 4 人才能使用自动生成。
- 目前按周生成和发布排班，尚未提供全年批量生成按钮。
- 换班目前限制在同一班次内，白班与夜班之间不能直接交换。
- 请假批准时，如果员工当天是唯一值班人员，系统会要求先完成换班，避免现场无人值守。

这些限制优先保证当前四人场景稳定可靠，后续可以继续扩展多人岗位、技能要求、工时成本和年度批量排班。
